### 9.4 Scalable near-dedup protocol

The earlier all-pairs implementation is superseded by this deterministic candidate protocol:

```text
feature                  = unbounded character 5-grams
hash_family              = sha256_feature_once_splitmix_integer_permutations_v1
num_perm                 = 128
seed                     = 42
num_bands                = 32
rows_per_band            = 4
candidate_rule           = equal complete band signature in at least one band
verification_threshold   = estimated MinHash Jaccard >= 0.80
```

Candidate buckets are streamed by band and deterministic record ID; all candidate pairs within a
bucket are generated until the explicit candidate bound, with no random sampling or silent
truncation. The output is compact and bounded. Near-dedup rate is defined as `affected_record_rate
= distinct records in verified near-duplicate pairs / retained population denominator`. Pair
count, candidate count, evaluated count and affected-record count are reported separately.

Candidate explosion or output-bound exceedance fails closed. The band rule is complete for the
frozen band-equality candidate protocol; it is not a claim that an LSH candidate pass proves zero
false negatives for every possible pair above 0.80.
