Building the first synthetic fact system

Building the First Synthetic Fact System

We will start with a bioS-style setup. The dataset will be fully synthetic, controlled, and generated with simple rules.

At this stage, the goal is not to create highly natural text. The goal is to create data that is:

  • clean
  • traceable
  • reproducible
  • easy to evaluate

The first version will use a fully heuristic and template-based approach. No language model will be used for data generation.

1. Core Structure

The system will have two main layers:

  1. a canonical fact table
  1. a text generation layer

The canonical fact table will be the source of truth.

All English training sentences, Turkish repetition sentences, and evaluation questions will be generated from this table.

This design makes the dataset easier to control, inspect, and update.

2. Canonical Fact Table

Each row in the canonical fact table represents one synthetic fact.

The table contains the following columns:

  • fact_id
  • subject
  • relation
  • object_en
  • object_tr
  • name_type
  • frequency_bucket
  • branch_group

Column definitions

  • fact_id: a unique identifier for the fact
  • subject: the synthetic person or entity
  • relation: the type of factual relation
  • object_en: the canonical English answer
  • object_tr: the canonical Turkish answer
  • name_type: whether the subject name is English-like or Turkish-like
  • frequency_bucket: how often the fact appears in English training
  • branch_group: whether the fact is repeated during Turkish adaptation

The first version will use two relations:

  • profession
  • born_in

Starting with two relations keeps the experiment simple and allows us to test the complete pipeline before adding more relations.

3. Synthetic Entities and Values

The subjects and objects must be synthetic.

This reduces the risk that the model already knows the facts from its original pretraining data.

Subject names

The dataset will contain two types of subject names:

  • English-like names
  • Turkish-like names

This allows us to test whether the linguistic form of a name affects factual retrieval or cross-lingual transfer.

The names should sound plausible, but they should not represent known people.

Object values

The object values will also be synthetic.

For example:

  • synthetic profession names for profession
  • synthetic place names for born_in

Example facts include:

  • Leran Dovik → profession → river architect
  • Corin Veylor → born_in → Telmora

Each fact will have one clear canonical answer in English and Turkish.

4. Template-Based Text Generation

After the canonical fact table is created, the system will generate natural-language sentences using fixed templates.

For example, the fact:

  • subject: Leran Dovik
  • relation: profession
  • object_en: river architect
  • object_tr: nehir mimarı

can produce the following English sentences:

  • Leran Dovik works as a river architect.
  • The profession of Leran Dovik is a river architect.
  • Leran Dovik is employed as a river architect.

For Turkish repetition data, it can produce:

  • Leran Dovik nehir mimarı olarak çalışır.
  • Leran Dovik'in mesleği nehir mimarıdır.

This method gives us full control over the generated content and avoids hallucinated or unintended facts.

5. Multi-Template Generation

We will use a multiM-style approach.

This means that the same fact will be expressed using several different templates.

The purpose is to prevent the model from learning only one sentence pattern.

For example, the fact:

Corin Veylor → born_in → Telmora

can appear as:

  • Corin Veylor was born in Telmora.
  • The birthplace of Corin Veylor is Telmora.
  • Telmora is the birthplace of Corin Veylor.
  • Corin Veylor's place of birth is Telmora.

The underlying fact stays the same, but its surface form changes.

This is important because factual learning should not depend on memorizing one exact sentence.

6. Full-Name Heuristic

The first version will use the fullname heuristic.

The full subject name will be repeated instead of using pronouns such as:

  • he
  • she
  • they

For example:

  • Leran Dovik works as a river architect.
  • Leran Dovik was born in Arvenford.

This reduces ambiguity and avoids coreference problems.

It also makes the relationship between each sentence and its canonical fact easier to trace.

7. Frequency Control

Each fact will be assigned to one of three frequency groups:

  • low
  • medium
  • high

The frequency bucket controls how many times the fact appears in the English training data.

The first version uses:

  • low: 3 exposures
  • medium: 8 exposures
  • high: 15 exposures

This allows us to test whether facts that receive more English-side exposure are more likely to become retrievable in Turkish.

Frequency and template diversity

Frequency and multi-template generation are different.

  • Frequency controls how often a fact appears.
  • MultiM controls how many different surface forms express the fact.

A high-frequency fact should not be represented by only one sentence copied many times.

Instead, its exposures should be distributed across several templates.

Some exact repetition may still occur when the number of exposures is larger than the number of available templates, but the templates should be used as evenly as possible.

Effective exposure

The number of training epochs must also be considered.

For example, if a fact appears 15 times in the dataset and the model is trained for 5 epochs, the model may see that fact approximately 75 times.

Therefore, the final experiment should report both:

  • corpus frequency
  • effective training exposure

8. Experimental Branches

Each fact will belong to an experimental branch.

Branch A

The fact is:

  • taught in English
  • not repeated in Turkish adaptation data

This is the main transfer condition.

If the fact later becomes retrievable in Turkish, the result may indicate cross-lingual transfer from prior English knowledge.

Branch B

The fact is:

  • taught in English
  • repeated during Turkish adaptation

This condition represents Turkish-side reaffirmation or possible relearning.

9. Probe Generation

The same canonical fact table will also generate evaluation questions.

The training sentences and probe questions will refer to the same fact, but they will use different surface forms.

For example:

English probe

  • What is Leran Dovik's profession?

Turkish probe

  • Leran Dovik'in mesleği nedir?

The expected answers will come directly from:

  • object_en
  • object_tr

This keeps evaluation consistent and makes exact-match scoring possible.

10. Generated Outputs

The pipeline produces four files:

  • english_training.jsonl
  • turkish_repetition.jsonl
  • probes_en.csv
  • probes_tr.csv

English training data

All Branch A and Branch B facts appear in the English training data.

Turkish repetition data

Only Branch B facts appear in the Turkish repetition data.

Branch A facts must not appear in this file.

Probe files

All facts receive both English and Turkish evaluation questions.

This allows us to compare retrieval:

  • before Turkish adaptation
  • after Turkish adaptation
  • across English and Turkish
  • across Branch A and Branch B

11. First Pilot Dataset

The first pilot contains:

  • 24 synthetic subjects
  • 12 English-like names
  • 12 Turkish-like names
  • 2 relations
  • 48 total facts
  • 24 Branch A facts
  • 24 Branch B facts

The dataset is also balanced across:

  • low frequency
  • medium frequency
  • high frequency

Each subject currently has:

  • one profession fact
  • one birthplace fact

This creates a small biography-style structure while keeping the relations easy to evaluate independently.

12. First Implementation Goal

The first goal is not to create a large dataset.

The first goal is to verify that:

  • the canonical facts are correctly generated
  • English training data contains all facts
  • Turkish repetition data contains only Branch B facts
  • multiple templates express the same facts
  • fact IDs remain consistent across all files
  • English and Turkish probes use the correct answers
  • no unintended fact leakage occurs

Once the full pipeline works correctly with the pilot dataset, we can gradually add:

  • more templates
  • more synthetic subjects
  • more relations
  • larger frequency ranges

The experiment should remain controlled and simple before increasing its scale.
